world 01 · the builder

Math that has to be right for one person.

I like problems where the model and the product meet: a forecast that has to fit one woman's body, or an agent that someone trusts with their inbox. These are the systems I've built.

FemoraAI · cycle intelligence

A forecasting model for every single user

  • With my co-founder, I built a Kalman filter cycle model for each user, learning from her own logs instead of a population average.
  • I designed the Bayesian priors that start new users: a Normal-Inverse-Gamma update on log cycle length, grouped by age band and diagnosis such as PCOS.
  • A prior is published only once a group has 50+ users, with optional differential privacy noise on top.
  • I modeled late periods with a truncated normal distribution, so each user sees the chance her period arrives within 3 or 7 days, with 80% intervals.
Luna · proactivity engine

An assistant that acts before you ask

  • Events from a user's tools become life events that fire rule-based triggers with no model call, so Luna reacts fast and cheaply.
  • An hourly heartbeat checks what's pending and hands work to a task runner.
  • The morning brief gathers everything first, then makes a single model call to write it.
Luna · trust layer

Safe enough to touch your inbox

  • Every database query is scoped to its user, and unsafe operators are stripped out.
  • Untrusted email text is fenced off against prompt injection before the model ever reads it.
  • An action journal keeps every send safe through a crash.
  • Risky actions wait on an approval card, so nothing goes out without your yes.
FemoraAI · app & backend

Shipped to both app stores

  • I designed the product and built the React Native app in TypeScript, every screen a user touches, and took it live on iOS and Android. Apple approved it on the first try.
  • I built across the Spring Boot microservices backend on Kafka, Redis and MongoDB, from the service design to the user service behind SOS alerts and Partner Connect.
